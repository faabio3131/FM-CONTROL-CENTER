## Cakto / FM Command V1 - commercial gate
- Authority: FM Command V1 owns platform invoices, payments, recurring cycles and license outbox; IRON owns entitlements. Never route this through Command V2 or academy-to-student finances.
- New additive V1 migration: 0021; never transplant V2 migration/snapshot.
- S2S checkout is OWNER plus step-up at IRON, authenticated with an independent token at FM Command; checkout requires the canonical invoice and official offer binding. Redirect alone never grants entitlement.
- Financial webhook events require official HMAC over raw request, timestamps and a unique payment reference; no customer-provided tenant scope, emails or CPF as authority.
- Connectivity-only compatibility: for `pix_gerado`, `boleto_gerado` and `checkout_abandonment`, if BOTH HMAC headers are absent, compare SHA-256 digests of the body secret in constant time and return ignored without a PaymentEvent. Never downgrade partial, invalid or stale HMAC. Body-only financial events remain rejected. The provider's dashboard fixture is not proof of actual HMAC delivery; live financial delivery remains a release gate. See https://docs.cakto.com.br/conceitos/webhooks.
- Delivered entitlements are idempotent and retryable via persistent outbox; worker must only activate the still ACTIVE paid subscription, never one cancelled or refunded meanwhile.
- OFFLINE CONFIGURATION REQUIRED: create real Cakto account offer IDs, checkout URLs, webhook secret, FM tenant/product bindings, control-plane token, and recurring worker schedule via secured runtime settings before opening live checkout.
- Actual Cakto purchase, refund and cancellation need separate provider-authorized execution evidence; synthetic HMAC/test PostgreSQL does not certify provider production.
- Gross billed metric is invoice face value at issuance (including pending, paid and refunded invoices/orders), not net revenue or cash received. Include canonical one-time AI credit orders in the same UTC-period snapshot as recurring invoices; they never contribute paid subscription coverage. Refunds do not net this gross metric. No external provider settlement claim.

- Public HMAC ingress stores only normalized observation + SHA-256 in additive 0023; HTTP 200 queued is not payment confirmation. Nonfinancial connectivity notifications remain ignored. READ credentials are separate from RECEIPT and webhook secret.
- Scheduler uses repository variable FMCC_CAKTO_READBACK_ENABLED=true and runtime flag FMCC_CAKTO_READBACK_ENABLED=YES; neither is enabled by this change. Worker retrieves order and, for recurring, subscription and parent order, validates exact product, checkout path, price, currency, invoice, order membership and current status. No provider response or PII persisted; financial event fingerprint binds original and verified evidence. Fail closed on missing credentials, mismatch, stale/unsupported state, 429/5xx/timeout. Bounded retry + lease + owner step-up audited recovery, no external network in financial SQL transaction. If webhook persistence fails, provider manual re-delivery/reconciliation remains mandatory, not automatic.
